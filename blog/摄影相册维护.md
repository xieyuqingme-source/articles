# 摄影相册维护

摄影入口为 `/photos/`，每本相册使用固定 ID，例如 `/photos/beijing-memory/`。相册不计入文章数量或 RSS，沿用全站主题。原图和 Obsidian 笔记留在资料库；网页只使用 `photos/catalog.json` 的展示字段和 `photos/images/` 的压缩 WebP。不要直接编辑生成的 `_site_unified/`。

## 日常更新

1. 在原摄影文件夹中修改相册笔记，新增照片仍按原来的 Obsidian 附件方式插入。日期、地点和说明写在对应图片后。无需将原图复制到网站仓库。
2. 在本网站仓库运行 `./scripts/preview_photos.ps1`。它先导出已选择的相册，再调用原有 `scripts/build_site.py` 构建并检查全站，最后启动只绑定本机的预览服务器。若只需要生成结果，使用 `./scripts/preview_photos.ps1 -BuildOnly`。
3. 打开 `http://127.0.0.1:8767/photos/`。检查相册、照片方向和颜色、日期、地点及说明，特别留意说明文字中不适合公开的个人信息。桌面可点击照片，用左右方向键切换、Esc 关闭；手机可点击按钮或左右滑动，浏览器返回先关闭大图。
4. 预览结束在终端按 `Ctrl+C`。本地导出不会提交、推送或发布。确认以后才手动选择公开文件提交并 Push；推送 `main` 会触发已有的 Pages 发布流程。

也可以在依赖已准备好的 Python 环境运行：

```powershell
python scripts/update_photos.py --serve
# 或分步进行
python scripts/export_photos.py
python scripts/build_site.py --site-url https://xieyuqing.me
python scripts/check_site.py --site-url https://xieyuqing.me
python scripts/preview_site.py
```

更换端口可使用 `./scripts/preview_photos.ps1 -Port 8768`。脚本只提供本地预览服务，不开放局域网访问。

## 选择相册与本机环境

源路径和相册选择记录在仓库根目录的 `.photos-local.json`；它已被 Git 忽略。本次仅选择“北京记忆”和“大马随拍”。新笔记不会自动成为公开相册；需要先在本机清单中明确加入，并检查导出结果。

示例（路径相对于此配置文件，按自己的资料库结构修改）：

```json
{
  "vault_root": "..",
  "album_root": "../摄影集",
  "albums": [
    {"note": "北京记忆.md", "id": "beijing-memory"},
    {"note": "大马随拍.md", "id": "malaysia-snapshots"}
  ]
}
```

`id` 是相册的网址，使用小写字母、数字和连字符；改标题时保留 ID，笔记改名后只更新 `note`。可选的 `runtime.python` 和 `runtime.pythonpath` 指定本机已有解释器和依赖目录，由 PowerShell 预览脚本读取；这些机器路径也只保存在忽略配置中。没有指定时使用 `python`。首次建立环境可按 `blog/requirements.txt` 安装现有依赖，导出需要 Pillow 的 WebP 和 LittleCMS 支持。

## 笔记格式

保留现有结构即可：

```markdown
![[照片.jpg]]

2023年5月12日，17:09，北京房山区
这里写对应照片的说明。

可以保留多段说明。

![显式照片标题](相对路径/另一张照片.jpg)

2023年6月6日，20:20，北京丰台区宛平城
另一张照片的说明。
```

支持 Obsidian 图片嵌入、带路径的嵌入、宽度别名，以及标准 Markdown 相对路径和 URL 编码的文件名。先按笔记相对路径、资料库相对路径查找；只写文件名时，必须能在资料库中唯一匹配。缺图、重名、远程图片和资料库外引用会报错，不会猜测使用哪张图。代码块和普通注释中的图片不会被收录。

相册标题依次读取 frontmatter 的 `title`、一级标题或笔记文件名；只使用明确填写的简介、日期与地点。照片后的注释与正文就是照片故事：逐张对应并完整保留文字、换行和空行，列表以低调的小字展示，大图中显示完整故事，不截断。日期与时间来自显式文字，不读取 EXIF 来补日期、不推断时区。没有填写的照片标题、地点或日期留空。标题和故事按纯文本转义，不执行笔记中的 HTML。

当前两本相册的 12 则故事都写在图片后的普通正文中，无需改动。若以后把故事写在注释语法里，请明确标为 `story:` 或 `照片故事：`，以便和内部备注区分。例如（紧随对应图片，支持多行和空行）：

```markdown
![[照片.jpg]]
<!-- 照片故事：
这里是第一段照片故事。

这里是第二段，全文会显示在网页。
-->
```

同样支持 `<!-- story: ... -->`、`%% story: ... %%` 和 `%% 照片故事：... %%`。明确标记的故事按在笔记中的顺序加入该张照片故事；没有故事标记的内部 HTML / Obsidian 注释不会公开。日期、地点等展示字段和 `photo:` 公开控制注释仍各自处理。

## 草稿与撤下

相册在 frontmatter 中使用 `draft: true`、`private: true`、`public: false`、`publish: false`，或 `status: draft` / `private` / `草稿` / `不公开`，会被排除。也支持草稿或不公开标签。格式示例：

```markdown
---
title: 计划中的相册
draft: true
---
```

单张图片的公开控制放在图片紧随的注释中：

```markdown
![[暂不公开.jpg]]
<!-- photo: public=false -->

2023年5月12日，17:09，北京
这张照片的说明。
```

也可使用 `<!-- photo: draft=true -->`。更新后，被撤下的照片不会留在摄影网页资源中；只有导出器已登记拥有的派生文件会被清理。未登记文件会触发检查，避免误删。照片从笔记删除、相册从清单移除后，重新导出和构建即可撤下。原笔记与原图始终保留。

## 导出与隐私边界

图片生成最长边不超过 640 和 1920 像素的两档 WebP，不放大小图；先校正方向，再将 ICC 颜色转为 sRGB，最后移除 EXIF、GPS、XMP 和原 ICC 等元数据。网页数据仅包含相册/照片 ID、标题、说明、明确填写的日期时间地点、派生图片 URL 和尺寸，不含原始路径、完整 EXIF、其他笔记或本机清单。

`.photo-cache/` 保存本机来源映射和增量缓存，已被 Git 忽略。照片 ID 与顺序无关；同一来源照片更换内容时保持 ID，重命名时通过原内容匹配恢复 ID。重新导出只重新编码变化的图片；只改故事不重新编码图片。保留缓存有助于持续保留原 ID；同时改名和替换内容时，应分两次导出，先完成其中一种变更。不要手改 ID 或缓存；迁移电脑时私下保留该目录，缓存缺失而已有导出时脚本会停止保护现有数据。

普通网站构建仅读取公开导出，不会扫描私人资料库，也不会将整个摄影文件夹复制到站点。公开 `catalog.json` 和网页图片在 GitHub Actions 中可重复构建，无需访问本机照片。

## 检查与发布

```powershell
python -m unittest discover -s scripts -p "test*photos*.py"
node scripts/test_photos_logic.cjs
python scripts/build_site.py --site-url https://xieyuqing.me
python scripts/check_site.py --site-url https://xieyuqing.me
```

若本机已有 Playwright 和 Chrome，还可运行 `node scripts/test_photos_browser.cjs`，截图和报告写入忽略的 `.local-checks/photos-browser/`。此项使用独立的临时浏览器上下文，不操作日常浏览器，所有网页请求只读取本地生成文件。

提交前用 `git status --short` 和 `git diff`，逐项检查 `photos/catalog.json` 的文字与 `photos/images/` 的图片。这些是可供人工确认的公开候选内容。只提交相册功能源码、维护文档、明确允许公开的 catalog 和压缩图片；不提交 `.photos-local.json`、`.photo-cache/`、原图、原始笔记、`_site_unified/` 或 `.local-checks/`。已有 README 等其他改动由用户另行处理，不能被本次提交自动包含。

本地预览确认后，由用户在正确的 canonical 仓库手动 Commit、Push origin。已有 `Publish personal site` Actions 构建并发布 `_site_unified/`；等待 build 和 deploy 成功再检查线上页面。本次准备本地相册不代表已批准发布。
