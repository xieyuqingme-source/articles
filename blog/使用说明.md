# 博客使用说明

日常流程：写作 → 按原 SOP 整理到公开稿目录 → GitHub Desktop 提交并 Push → Actions 自动更新博客。

- 中文稿继续放在“中文文章”，英文稿继续放在“English Articles”；图片和附件目录不变。
- 文章继续使用 `YYYY-MM-DD-标题.md` 文件名与 `# 标题`。更新旧文时保留文件名，博客网址随之保持稳定。
- 博客按文件名日期倒序排列，不用添加额外的文章头部配置。AI 评语会和正文一起显示。
- 首页和语言栏目自动收录两个文章目录中的 `.md` 文件。“关于我”从 README 生成；README 的 GitHub 文章索引仍按原 SOP 更新。
- 图片、附件或文章链接缺失时，构建会报错，避免发布带有失效链接的新版本。
- 支持 Obsidian 的 `[^注释编号]` 脚注及对应定义，表格中的 `<br>` 也会显示为换行。其他原始 HTML 仍按文字显示。

首次：仓库 Settings → Pages → Source 选择 GitHub Actions；提交并 Push 博客文件后，在 Actions 中查看 `Publish blog`。成功后默认地址为 <https://xieyuqingme-source.github.io/articles/>。

## 复制到公众号

打开博客文章 → 点击“复制到公众号” → 在公众号正文中用普通 `Ctrl+V` 粘贴 → 单独填写标题、作者和封面 → 保存草稿并在手机上预览。

- 专用排版为白底、16px 正文、两倍行距；保留原文、标题层级、图片顺序和表格。博客阅读页继续使用原来的配色。
- 旧草稿先在正文区域全选并替换，不要叠加粘贴；不用“粘贴为纯文本”。
- 可展开“公众号排版预览”查看白底版本；自动复制失败时，只选中该预览里的正文手动复制。
- 图片引用已发布博客的完整网址，粘贴后仍需核对图片是否成功保存、表格是否适合手机阅读。这一步只复制内容，不会替你发表。

`blog/config.json` 管理标题和简介，`blog/style.css` 管理外观，`scripts/build_blog.py` 生成并检查网页，`.github/workflows/pages.yml` 自动发布。现有文章、图片和 README 是内容来源。

`blog/wechat-copy.js` 管理公众号富文本复制；专用排版在生成器的 `WechatContent` 中设置。日常新增文章无需修改这些文件。

`_site` 是生成的网页，`.blog-deps` 是本地检查用的依赖，两者已被忽略，不提交；工作流只上传 `_site`，不会上传整个仓库目录。

供 AI 维护：先核对原 SOP；保持现有文章目录、文件名和图片字节，不把原 Obsidian 笔记或整个附件库导出。博客生成器只读取公开稿目录；链接转换只发生在生成网页时，不改写 Markdown 源文件。需要改外观时修改模板或样式，不要重写文章。

本地技术检查（可选，日常写作无需执行）：

```text
python -m pip install -r blog/requirements.txt
python scripts/test_build_blog.py
python scripts/build_blog.py
```
