# 网站与作品维护

本仓库是个人网站的源码仓库。首页和作品总览负责展示与导航，文章继续由原有文章构建流程生成；公众号排版工具和 Coze 工作流的代码、使用说明各自在自己的仓库维护。

## 去哪里修改

以下路径均相对于网站仓库根目录。

| 要做的事 | 修改位置 |
| --- | --- |
| 修改首页简介或文章、作品入口 | `home/index.template.html` |
| 修改独立关于页的中英文个人介绍与联系方式 | `home/about.json`；首页短简介仍单独维护，不由此文件覆盖 |
| 修改关于页结构 | `home/about.template.html` |
| 修改首页、作品页、关于页的样式和响应布局 | `home/assets/portal.css` |
| 修改作品名称、用途、功能、贡献、使用方式与链接 | `home/projects.json` |
| 修改作品页结构 | `home/projects.template.html` |
| 新增或修改公开中文文章 | `中文文章/` |
| 新增或修改公开英文文章 | `English Articles/` |
| 修改构建与链接校验 | `scripts/build_site.py`；文章构建仍由 `scripts/build_blog.py` 负责 |
| 修改大图派生策略 | `scripts/image_assets.py`；策略和缓存行为由 `scripts/test_image_assets.py` 检查 |
| 修改文章页、目录和手机控件样式 | `blog/style.css` |
| 修改文章目录位置、折叠与当前章节提示 | `blog/site.js`；模拟 DOM 检查见 `scripts/test_toc_logic.cjs` |
| 修改正式网址或 Python 依赖 | `blog/config.json`、`blog/requirements.txt`；改网址后重新完整构建并检查 |

`_site_unified/` 是生成结果；不要直接改里面的 HTML，也不要把它当源码提交。首页地址为 `/`，文章入口为 `/articles/`，作品总览为 `/projects/`，独立关于页为 `/about/`。新增作品和关于页不会成为文章，也不应进入文章数量或 RSS。

## 关于页与文章目录

关于页使用主站导航与样式，正文只来自 `home/about.json`，不再把仓库 README 或其中的「文件说明」渲染成个人介绍。修改时填写真实的中英文介绍与联系方式，使用纯文本；构建器负责 HTML 转义。首页 `home/index.template.html` 中的短简介独立保留。旧 `/articles/about.html` 只提供带 `noindex` 的兼容跳转与手动入口，目标为 `/about/`，不进入 sitemap，也不保留另一份个人介绍。README 的仓库文件说明继续保留。

有章节标题的文章在电脑端默认把目录放在右侧，可通过正文外的控件切换到左侧或隐藏。位置选择保存在当前站点的 `localStorage`；存储不可用时页面仍可操作。宽度不超过 760 像素时，目录使用原生 `details`/`summary` 展开入口，选中章节后收起；电脑端的隐藏偏好不会让手机目录消失。没有章节标题的文章不生成空目录或空控件。禁用 JavaScript 时仍能展开目录并使用原生章节链接；自动收起、位置偏好与当前章节提示需要脚本。

网站已移除文章的公众号复制、预览及专用代码。需要公众号排版时，使用独立的雨聊公众号排版工具；它的富文本复制、含图片导出与来源许可继续在工具仓库维护。文章原图、派生图和常规阅读功能不因此撤下。

## 增加或更新作品

在 `home/projects.json` 的 `projects` 数组中复制一个现有对象，再逐项修改。作品数量自动统计，不需要手动改首页数字。每个作品应包含真实名称、用途、主要功能、实际贡献、使用方式和醒目的「查看 GitHub」入口。

| 字段 | 用途 |
| --- | --- |
| `id` | 唯一标识，使用小写字母、数字和连字符 |
| `title`、`english_title`、`kind` | 中文名称、英文名称和作品类型 |
| `summary`、`problem`、`features` | 简介、解决的问题、主要功能；均写纯文本 |
| `contribution`、`usage` | 自己实际完成的适配或编排，以及真实使用步骤 |
| `icon` | 现有文档图标用 `editor`，工作流图标用 `workflow` |
| `source_url`、`guide_url` | 公开 GitHub 仓库与使用说明的 HTTPS 链接 |
| `download_url` | 可选，已有实际下载文件才填写 |

文本会经过 HTML 转义，不要在数据中嵌入 HTML。链接使用公开 HTTPS 地址，不放凭据、查询参数或本机绝对路径。图标由页面代码绘制；新增图标种类需要同时调整构建和样式，不用用户文章截图作装饰。

当前两个作品的范围应保持准确：

- [雨聊公众号排版](https://github.com/xieyuqingme-source/yuliao-wechat-editor) 是本地运行工具，支持 Obsidian Markdown 图片匹配、中文样式预览、相关文章整理、富文本复制和含图片 HTML 导出。页面提供源码和使用说明；目前没有在线运行版，不添加「在线使用」按钮。源码已上传不代表网页已部署。项目参考 Raphael，并使用 markdown-it；实际参考范围和许可证以工具仓库的 `THIRD_PARTY_NOTICES.md`、`LICENSE` 及随附许可为准，不写成所有组件均从零原创。
- [Coze 论文速记工作流](https://github.com/xieyuqingme-source/coze-paper-quick-reference) 将 PDF/Word 输入连接到链接读取插件、豆包模型、论文速记卡和飞书云文档。下载后需要在 Coze 中配置模型、插件及文档相关设置。它整合已有平台与组件，不是可直接部署的静态网页；不编造在线演示地址。

## 本地构建与人工预览

在网站仓库根目录使用 Python 3.10 或更新版本和 Node.js。Python 依赖固定版本记录在 [requirements.txt](requirements.txt)，包括带 WebP 编码支持的 `Pillow==12.3.0`。第一次准备环境或更换 Python 解释器时先确认依赖；已有完整依赖时无需重复安装。GitHub Actions 使用 Python 3.12，并按同一份文件安装。

```powershell
python --version
node --version
python -m pip install -r blog/requirements.txt
python -c "from PIL import features; print('WebP:', features.check('webp')); print('LittleCMS:', features.check('littlecms2'))"
```

检查与构建命令：

```powershell
python scripts/test_build_blog.py
python scripts/test_build_site.py
python scripts/test_about_routes.py
python scripts/test_image_assets.py
node scripts/test_waline_logic.mjs
node scripts/test_toc_logic.cjs
python scripts/build_site.py --site-url https://xieyuqing.me
python scripts/check_site.py --site-url https://xieyuqing.me
python scripts/test_archive_pages.py
```

构建命令会检查生成页面、本地链接、锚点和输出边界，并输出派生图片的实际字节统计。最后一个检查需要构建结果和可在终端中找到的 Node.js。当前默认正式根地址为 `https://xieyuqing.me`，文章配置使用其 `/articles` 路径；检查入口可用 `--site-url` 显式指定根地址。若以后更换正式站点地址，应同步更新配置并按新根地址构建和检查；根地址参数不要附加 `/articles/` 或 `/projects/`。这项配置不改 DNS。

需要自己查看页面时再运行：

```powershell
python scripts/preview_site.py
```

手动打开 `http://127.0.0.1:8767/`、`http://127.0.0.1:8767/projects/` 和 `http://127.0.0.1:8767/about/`，查看首页简介、导航入口、项目链接、独立个人介绍、窄屏布局、主题切换和键盘焦点，并抽查 `/articles/`。文章页还应人工核对大图清晰度、图片加载前的占位尺寸、手机搜索与年份控件、目录左侧/右侧/隐藏及刷新后的偏好、手机目录展开与选中章节后收起，以及没有标题时的布局。也可禁用 JavaScript 检查原生目录链接。旧 `/articles/about.html` 应转到主站关于页。用完在终端按 `Ctrl+C`。命令不会自动打开浏览器；代码、链接和模拟 DOM 检查不等于已完成真实浏览器视觉验收。

## 大图派生

构建器为 `images/`、`附属资料/` 中超过 5 MiB 的静态 JPG/PNG 生成 WebP 派生图。当前策略是 960 和 1920 像素宽、质量 90、编码方法 6、Lanczos 缩放；不放大较小原图，按 EXIF 方向校正，带 ICC 配置的图片先转为 sRGB 并保留透明度，再去掉派生图元数据。此步骤需要 Pillow 的 LittleCMS 支持。其他图片不因此重编码。正文通过 `srcset` 和 `sizes` 选择合适大小，已识别尺寸的 WebP 会写入宽高以减少布局跳动。

原始图片、原有图片 URL 和原 Markdown 保留。派生图仅写到 `_site_unified/articles/assets/responsive-images/`，文件名由内容和策略决定；目录中有生成标记与 `manifest.json`。同一内容、策略及有效缓存会复用，变更后只清理该生成目录中已登记的过期派生文件，不删除源图、其他目录或未知文件。遇到缓存归属、链接或未知文件检查失败时先保留目录排查，不自行删除陌生文件。

日常只更新原图和文章，再重新构建；不手工编辑派生图或 manifest，不把生成目录提交到 Git。只对符合阈值的图片生成两档资源，避免为全部附件增加副本。构建报告的 `source_bytes`、`variant_bytes_by_width` 和 `derivative_bytes` 是实际文件大小，不能当成真实网络加载时间或 Lighthouse 分数。发布包仍携带原图并额外包含派生图，优化的是网页正文可选用的图片字节，并非承诺整个发布包变小。

## 撤下或改名文章后的重建

完整检查会核对生成 HTML、canonical、sitemap 与 feed。平常构建保留已有生成目录，撤下或改名文章后可能留有旧 HTML，检查会提示其与新 sitemap 不一致。不要放宽校验或为绕过错误改动原文。先确认报错文件确实属于可重新生成的输出，再安排从干净的生成结果重建；不要清理源码、唯一资料或不明文件。本轮不因这项说明清理现有目录，也不新建备份；既有备份和 Git 历史保持原样。

## 提交与发布

在 GitHub Desktop 选择本网站仓库 `xieyuqingme-source.github.io`，核对本地目录确实是正在修改的源码目录。工具修改则选择 `yuliao-wechat-editor`，不要把工具文件复制进网站仓库，也不要编辑旧运行副本。

提交前先查看 Changes 和文件差异，仅选择本次已完成的源码与公开文档；已有但不属于本次工作的修改应单独处理。`README.md`、`blog/使用说明.md`、`blog/单仓库迁移与回滚.md` 的历史修改不会因本说明而自动成为本次提交内容。

先用 `git status --short`、`git diff --name-status` 和 `git diff` 核对当前差异，再在 GitHub Desktop 中选择对应文件。上一轮作品页与图片优化已提交，本轮的关于页、网站公众号功能移除和目录更新使用本轮最终报告中的实际清单，不照搬旧清单。

人工确认后，在正确仓库 Commit，再 Push origin。网站推送到 `main` 会触发已有的 `Publish personal site` Actions；检查 build 和 deploy 都成功，再人工打开线上首页、作品页、关于页和文章页。构建失败时先读失败步骤，不重复推送私人文件。本轮只进行本地修改和验证，未替你提交、推送或部署，也未进行浏览器自动化；本地检查结果不能证明线上已更新或视觉验收已完成。

工具仓库的 `Check` Actions 执行测试和本地分发构建；成功表示这套检查通过，不表示工具网站已发布，也不表示微信公众号后台效果已经验收。

## 公开内容与私人资料

只有准备公开的文章放入网站文章目录。工具测试使用合成样例，原稿和真实附件留在自己的资料库，导入时由用户主动选择；不得为了同步代码修改 Obsidian 原稿。

不要把整个私人 Vault、未经确认公开的私人图片、完整草稿 JSON、导出 HTML、目录索引、运行日志、令牌或本机绝对路径提交到任何公开仓库。已确认用于公开文章的图片是网站资源；新增资源仍应逐项确认。忽略规则不能替代逐项检查。工具来源说明、第三方版权和许可证需要继续保留。

机器上的源码目录、旧运行目录和备份位置由本机维护指南记录，公开文档不记录私人路径。日常只维护每个仓库的一份源码；生成结果、旧运行副本和备份均不作为发布来源。
